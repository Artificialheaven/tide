# 消息上下文与富消息指南

本文说明 DeepSeek 插件如何理解群里「没触发对话的闲聊」和图片/卡片/合并转发这类富消息，以及两个配套的消息回看工具。改动自 v11 存储迁移、`2026.10.26.2` 版本起生效。

## 1. 触发前的群聊背景（ambient context）

### 解决什么问题

群友先聊了三句「那个函数报 None」「你环境装了吗」，第四句 @ 机器人问「怎么修」。机器人此前没参与对话，光看第四句根本不知道在说哪个函数。现在：**当一条消息触发前台对话时，触发前最近几条没触发的群消息会作为一条 system 背景块注入**，放在摘要之后、对话窗之前：

```
【群内背景消息】以下是本轮对话触发前群里最近的群友闲聊……不要主动回答
这些消息里的问题、不要逐条回应、也不要自己提起它们……
[10-26 14:01] 群友3(QQ:1003): 那个函数一直返回 None
[10-26 14:02] 群友4(QQ:1004): 你依赖装了吗
```

### 边界规则（重要）

| 场景 | 是否注入背景 |
|---|---|
| 真人消息触发前台对话（@、回复、别名、判官判是） | ✅ 注入 |
| 粗筛未命中 / 判官判否 | ❌ 不注入，也不推进游标 |
| 定时苏醒 / 入群侦查 / 外部触发等后台轮 | ❌ 不注入 |
| 判官脚本、对话摘要、记忆抽取、风格学习 | ❌ 永远看不到背景原文 |

背景只服务于「理解这一轮」，不参与「要不要回复」的判断，也不会被总结进长期记忆，避免把无关群友的闲聊固化成人设。

### 游标与自愈

每群一行游标存在 `raw_cursors(group_id, last_id)`（v11 迁移，幂等）。注入区间是 `raw_messages` 里 `(游标, 触发消息id)` 的最近 N 条，**一轮前台对话成功结束后**游标才推进到触发消息 id：

- 首轮游标为 0 → 取触发前最近 N 条（不要求历史从装插件第一天起连续）；
- 对话轮异常失败 → 游标不动，下一轮会重复看到这段背景（自愈性重复，优于永久跳过）；
- 语料被滚动 trim / 清空导致游标超前 → 区间为空，安静跳过，不报错。

### 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `ambient_context_on` | `true` | 是否注入背景块，支持每群覆盖 |
| `ambient_context_n` | `8` | 最多注入条数；渲染另有约 1200 字整块上限，超了从最旧行开始丢（保留离触发最近的） |

全局设置页和每群设置页都能改。

## 2. 图片：可操作的 CQ 码 + read_message_image

入站图片在正文里不再只剩 `[图片]`，而是一个紧凑码：

```
[CQ:image,file=abcd1234.image]
```

- 优先用 `file`（NapCat 图片哈希名，短且稳定）；段里只有 URL 时回退 `[CQ:image,url=https://…]`；两者都没有才是 `[图片]`。闪照（flash）同等处理。
- **当前触发消息**里的图片照旧自动下载、直接以多模态附给模型，不需要工具。
- **历史对话窗、背景块、合并转发节点**里的图片只有码。模型需要看画面时调用工具 `read_message_image`（工具名 `message.read_image`）：
  - 参数 `ref` 填码里的 file 哈希，可附 `question` 说明想确认什么；
  - 插件用 OneBot `get_image` action 换临时地址 → 受 `media_download_max_kb` 总预算约束下载 → 魔数校验图片格式 → 以多模态图片回传，base64 只活在当轮 messages，不入库；
  - 同一 ref 本轮只拉一次（重复调用直接提示看上面的图）；
  - ref 有严格白名单（字母数字 `. _ ( ) { } -`，≤160 字符），拒绝路径、`..`、URL；
  - 只读操作，**不是风险工具**，任何群都能用；图片过期时提示请群友重发。
- 回复别人消息时生成的引用摘要走「人话模式」，图片仍显示为 `[图片]`，卡片不带链接（省 token）。

语音维持 `[语音]`。文件、视频不再只是光秃秃的占位符，而是带上下载参数：

```
[文件 name="需求.docx" file_id=abc123 busid=102 size=12345]
[视频 name="clip.mp4" file_id=abc123 busid=102 size=12345 path=mcp/inbound_video_3f2a9c1d88e04b17.mp4]
```

- `name` / `file_id` / `busid` 就是段数据（群文件场景下即 `get_group_root_files` 的列表字段）里的下载参数，模型可直接照抄给 `qq_download_file` 重新下载；当前轮触发通过后系统也会自动下载并解析文件内容。
- 视频在触发通过后由 `media_in` 下载（需 `inbound_video_on` 与 `read_video_on` 同时开启；单条上限 `inbound_video_max_kb`，默认 50MiB，独立于文档下载总预算），以确定性文件名存进本群 `mcp/` 工作区，占位符里的 `path` 即 `read_video` 的入参。`mcp/` 有 TTL 清理，历史里旧视频的 path 可能失效。
- 回复摘要（人话模式）和合并转发节点仍用朴素的 `[文件]` / `[视频]`，避免指向并不存在的下载/落盘结果。

## 3. 分享卡片：标题 + 链接不再被吞

json / xml 分享段（B 站 structmsg、QQ 文档 detail_1、小黑盒等小程序、音乐卡片、xml 灰条）递归提取标题和跳转链接，渲染成一行：

```
[卡片] 某 B 站视频 https://www.bilibili.com/video/BV1xx411c7mD
```

提取规则：标题优先取 `title`，退回 `desc/description/prompt`（`[QQ小程序]` 这类无信息 prompt 会被剥掉），跳过 `preview/button/icon/cover` 等噪声键；URL 认 `url/jumpurl/qqdocurl/link/source_url`，限 http(s)。标题 ≤80 字、URL ≤500 字、整条 ≤200 字，缺什么降级什么（`[卡片] 标题` → `[卡片] URL` → `[卡片]`），坏 JSON 不报错。

另有：

- 名片段 → `[名片] QQ:12345` / `[名片] 群:678`；
- 合并转发段 → `[CQ:forward,id=<id>]`，配合下面的工具展开；
- CQ 串通道用 NapCat 的实体编码（`&#44;` / `&#91;`），括号嵌套的 data 走括号平衡扫描，不会被逗号截断。

链接进了对话窗，模型自然能回答「这个视频讲了啥，帮我总结下」之类的请求，但插件本身不抓取卡片页面内容。

## 4. 合并转发：read_forward

工具 `read_forward`（工具名 `message.read_forward`），参数：

| 参数 | 说明 |
|---|---|
| `id` | `[CQ:forward,id=…]` 里的 id，白名单 `^[A-Za-z0-9_=.\-]{1,200}$`，拒绝 URL |
| `offset` | 从第几条开始（默认 0） |
| `limit` | 本页条数，默认 20、上限 20 |

行为细节：

- 调 OneBot `get_forward_msg`，**自己检查信封**（retcode 不等于 0 时 OneBot 不抛异常）；失败时透传 wording，并提示「通常是转发已过期或被撤回，请群友重新转发一次」；
- 节点归一为 `序号. [时间] 昵称: 正文`；节点正文走同一套富消息渲染——节点里的图片出 `[CQ:image,file=…]`（可再用 `read_message_image` 看图）、卡片出标题+链接；`nickname` 缺失退 `name`；嵌套转发只给 `[合并转发]` 占位，不递归展开；
- 无服务端分页：首次调用拉全量节点缓存在本轮 ToolContext，之后翻页切缓存、不再请求 API；
- 页脚形如 `第 1-20 条 / 共 53 条；继续看请用 read_forward(id=…, offset=20)`，末页显示「已全部展示」；单条正文截断 400 字，整页约 1800 字封顶；
- 只读、非主人门禁，任何群都能用。

## 5. 出站净化：模型不能复读 CQ 码

入站给模型看的 `[CQ:…]` 码是可操作的上下文，但模型输出的文本里如果原样复读这些码，NapCat 会当成真指令——`[CQ:image,…]` 会重发图片、`[CQ:at,qq=…]` 会真 @ 人。因此：

- 终态文本在发送和落库**之前**统一过 `sanitize_model_text`：半角 `[CQ:` 全部转成全角 `［CQ：`，码失效但肉眼几乎无差别；
- 净化在 `@昵称 → 合法 CQ:at` 渲染**之前**，所以正常 @ 群友不受影响；
- 系统提示词同时有硬规则：不要在回复里输出/模仿任何 `[CQ:…]` 码，要 @ 谁就写 `@昵称`，要发图走发图工具。
