## 二、四个"方面"

### 1. 质量基线：现在有什么问题

两份独立审查，一份看**代码对不对**，一份看**用起来顺不顺**：

- 缺陷审查是"可复现的 bug 清单"：45 条里有 7 条高危，包括 `web.py:537` 变量名错导致接口必崩、`_hard_split` 在 `split_max_len=0` 时死循环、插件 enable/disable 不触发 `on_stop`、私聊消息按群消息发送。
- 体验评估是"用户视角的摩擦点"：面板启动时序、日志刷屏、设置页 24 组无导航、token 裸展示、群列表没有群名、品牌名不一致。

**用途**：作为后续所有改造的验收基线——改完要能对着编号回填"已修/不修/另案"。

### 2. 界面与交互：面板应该长什么样

WebUI 方案把体验评估里的视觉/交互问题收敛成一套可执行的设计：

- 现状诊断：两套色板、9 份内联样式、8 份重复导航、11 个页面；两处对比度不达标（muted 4.11:1、白字/主色 2.53:1）。
- 目标方案：一套 token（深海蓝 + 潮汐青，全部过 AA）、一个 App Shell（236px 侧栏）、20 个组件、25 个内联 SVG 图标。
- 技术路径：不引 npm/构建链，新增 `ui/web/static/tds/*` + `base.html`，插件页 `{% extends "base.html" %}`。
- 分期：M0 基建 → M1 框架页 → M2 插件页 → M3 图表/移动端 → M4 打磨，共 17 人日。

视觉稿 HTML 是"设计基线"，不是最终代码；方案书是"施工图"。

### 3. 架构对标：和主流 agent 框架差在哪

以 Claude Code 为主参照，横向对比 OpenAI Agents SDK、LangGraph、AutoGen、CrewAI、OpenHands：

- 22 维矩阵（循环、并行工具、权限、子代理、hooks、压缩、记忆、恢复、可观测、评测……）。
- 结论：大肥鱼是"多群陪聊 agent"，不是缩水版 coding agent；**上下文工程（LIVE_CTX 尾部块）和多套记忆领先**，差距集中在四个通用器官：并行工具、权限分级、子代理、hooks。
- 明确不照搬：plan mode、文件编辑工具集、CLI 形态、图编排、多 agent 互聊。

### 4. 工程路线：具体改哪里、怎么改

增强方案把差距书里的 G-01～G-04 落成可执行项：

- 新增 5 个模块：`tool_batch.py`、`permissions.py`、`approval.py`、`subagent.py`、`hooks.py`。
- 修改 8 处既有代码：`_risk_denied`、`_chat_loop`、循环抽取、工具表、配置、迁移、事件、装配。
- 每个模块给了接口签名、配置键、失败降级、测试点；DB 迁移 5→6 有三张新表 DDL。
- 排期 15 个工作日 / 16 人日；四个开关全关可回滚到当前行为。
