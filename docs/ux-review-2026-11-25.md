- **仓库**：`F:\PythonProgram\tide`（master，审查时 HEAD `45b8c6d`）
- **评审视角**：首次上手、日常运维、群成员体感、配置调参、文档与默认值
- **方法**：沿真实用户旅程走查代码与页面（`main.py` → Web/GUI → 插件页面 → 群聊链路），对照默认配置和 README/docs

## 0. 摘要

最影响“第一次用的人会不会放弃”的五处：

1. **Web 面板必须等 QQ 连接成功才启动**——连不上时，恰恰没有面板可用来排查。
2. **默认主人 QQ 是作者的真实号码**——新用户漏改就永远不是“主人”。
3. **机器人入群先打招呼，然后对所有人的消息沉默**——群默认未启用，问候却像已经可用。
4. **直接 @ 也可能被模型用 `[nospeak]` 静默**——用户会认为机器人坏了。
5. **面板密码留空 + WS token 为空时永远登不进去**，且只提示“密码错误”。

日常运维侧最痛的是：日志没有过滤/搜索、群列表只有群号、保存/长操作缺少真实反馈、通用插件配置弹窗可能覆盖高级配置。

## 1. 首次上手

### U-01【阻断】Web 面板必须等 WebSocket 连接成功才启动

- **位置**：`main.py:128-137`；`README.md:254-267`；`docs/web-admin.md` 启动章节
- **现象**：`start_web_server()` 位于 `async with create_connector() as websocket:` 成功之后。NapCat 没启动、地址填错、token 不对时，面板根本不存在。
- **影响**：而面板正是排查连接问题、查看日志、改配置的工具；首次配置错误会直接进入“什么都看不到”的状态。重连次数耗尽后进程会停住等待信号，也没有任何恢复入口。
- **建议**：把 Web 面板启动移到连接循环之前，页面展示“未连接 / 重连中 / 已连接 / 已放弃”状态，并提供“立即重连”按钮；文档补充“面板不依赖 QQ 在线”。

### U-02【阻断】默认主人 QQ 是作者的真实号码

- **位置**：`plugins/deepseek/Core/config.py:33`、`plugins/deepseek/web.json:3`、`plugins/deepseek/config.json:2`
- **现象**：`owner_qq` 默认是一个真实 QQ 号，而不是 0/空。
- **影响**：新用户按 README 走到“配置 AI”时容易漏改；不改的话，所有主人指令和风险工具都指向一个陌生人，用户自己发 `/ai 开启` 反而没反应。首次体验会非常困惑。
- **建议**：默认置 0/空；启动时检查并在面板顶部/日志中醒目提示“请先设置你的 QQ”；未设置时禁用主人指令并给出说明。

### U-03【高摩擦】入群先打招呼，然后沉默

- **位置**：`plugins/deepseek/Core/engine.py:215-259`；`plugins/deepseek/deepseek.py:335`
- **现象**：入群问候不受群 `enabled` 约束，但 `get_or_create_group` 默认 `enabled=0`；问候之后，所有群消息在 `if not group_row['enabled']: return` 处被丢弃。
- **影响**：成员看到“大家好，有事 @ 我就行”，然后 @ 它没有任何反应；第一印象直接变成“这机器人是坏的”。
- **建议**：三选一：入群自动启用（配置项，默认开或首次提示）、问候里明确“让主人发 `/ai 开启` 启用我”、或私聊主人发一条带启用命令/面板链接的通知。

### U-04【高摩擦】非主人发 `/ai ...` 被静默吞掉

- **位置**：`plugins/deepseek/deepseek.py:509-522`
- **现象**：命中指令前缀但不是主人时直接 `return True`，不回复，也不进 AI。
- **影响**：成员会反复尝试或以为机器人坏了；主人也不知道有人在敲指令。
- **建议**：对已知指令回一句“这个指令只有主人能用”；其余非主人消息照常分流。可加冷却防刷。

### U-05【高摩擦】面板密码为空时永远登不进去

- **位置**：`main.py:132-136`；`ui/web/auth.py:27-35`
- **现象**：`web_admin_token` 为空时回退到 WS `token`；两者都为空时 `AUTH_TOKEN=""`，`try_login` 拒绝空密码，登录页永远提示“密码错误”。
- **影响**：用户按“启用 Web 面板”的直觉操作后，无法进入面板，也没有任何“密码未配置”的提示。
- **建议**：启动时检测空密码，自动生成随机 token 并打印/写入配置；登录页区分“未配置密码”和“密码错误”。

### U-06【中摩擦】GUI 模式无法在 GUI 里启用 Web 面板

- **位置**：`ui/config_window.py:7-32`
- **现象**：框架配置窗口只保存心跳、WS 地址、token、面板密码、transport、官方凭据等，没有 `enable_web_admin`、`web_admin_host/port`。
- **影响**：默认启动方式是 GUI，但 README 推荐用 Web 面板；用户必须手动编辑 `config.json` 才能启用，GUI 里没有任何入口。
- **建议**：把这三项加入 GUI 配置窗口；或首次启动提示“Web 面板可通过编辑 config.json 启用”。

### U-07【高摩擦】首次安装插件依赖长时间无反馈且阻塞事件循环

- **位置**：`utils/plugin_loader.py:243-271`
- **现象**：同步 `Popen` 逐行读 pip 输出，控制台只刷 pip 日志；没有“首次安装依赖，可能需要几分钟”的提示。安装期间事件循环被阻塞。
- **影响**：GUI/面板表现为“卡住”，用户容易强退；pip 网络挂起时可能长时间无输出。
- **建议**：安装前打印醒目提示；把 pip 放到子线程；面板显示安装进度或至少最后一行；设置硬超时。

### U-08【高摩擦】默认地址三处不一致，首次配置容易连错

- **位置**：`configs.py:19`、`config_defult.json`、`main.py:61`、`README.md:240`
- **现象**：代码默认 `ws://localhost:8080`，README 快速开始写 `ws://127.0.0.1:3001`，`main.py` 兜底是公网地址；`config_defult.json` 文件名拼写错误、`max_reconnect_attempts` 等值与代码默认也不同。
- **影响**：用户按 README 配置却连不上；兜底公网地址会让“缺省配置”的行为难以预期。
- **建议**：统一为 `127.0.0.1:3001`（或明确推荐值），删除/更新过期文件，删掉公网兜底，改为缺省即报错并提示怎么配。

### U-09【中摩擦】缺少“最小可用配置”检查

- **位置**：`ui/web/server.py:136-176`（只做单字段校验）
- **现象**：可以保存 `transport=official` 但没有 app_id/secret、可以启用面板但密码为空、可以不给任何模型 Key；面板都显示保存成功。
- **影响**：问题要到下一次启动/对话才以“fatal/静默失败”的形式暴露。
- **建议**：保存时做跨字段校验（official 凭据、面板密码、至少一个可用模型），并在面板顶部显示配置健康度。

## 2. 日常运维面板

### U-10【高摩擦】日志页没有过滤/搜索/暂停，心跳还会刷屏

- **位置**：`ui/web/templates/index.html:536-545`；`configs.py:18`；`core/events.py:56-62`
- **现象**：日志页只有自动滚动和清空；200 条环形缓冲混着每条群消息、心跳、工具调用。`show_heartbeat` 默认开启，心跳会持续占位。
- **影响**：繁忙群里根本没法用它排查问题；关键错误很快被刷走。
- **建议**：按群号/来源/级别/关键字过滤，增加暂停和导出；心跳单独开关或默认不进 Web 日志。

### U-11【中摩擦】插件加载失败看不到真正原因

- **位置**：`utils/plugin_loader.py:596-603/632-639`；`ui/web/templates/index.html:455-478`
- **现象**：真实异常放在 `plugin_info['error']`，但插件表只渲染 `name/version/description`，描述只写“插件加载失败/依赖安装失败”。
- **影响**：用户只能去翻控制台，面板帮不上忙。
- **建议**：在插件行展示 `v.error`（可折叠/悬浮），并提供“查看日志”。

### U-12【高摩擦】通用“插件配置”弹窗与专用设置页并存，且可能覆盖高级配置

- **位置**：`ui/web/server.py:286-329`；`plugins/deepseek/templates/settings.html`
- **现象**：deepseek 同时有专用设置页和 `web.json` 生成的 66 字段通用表单。通用表单会把 schema 子集整文件写入 `config.json` 再调 `load_config`；插件未加载/重载中时可能丢失 `llm_providers` 等键，接口却仍返回 `ok:true`。
- **影响**：用户不知道该用哪个入口；误用后“保存成功”但配置被破坏。
- **建议**：有专用页面时隐藏通用配置按钮，或明确标注“仅基础字段，可能覆盖高级配置”；保存失败必须返回 `ok:false`。

### U-13【高摩擦】群列表只有群号，没有群名/人设

- **位置**：`plugins/deepseek/Core/storage.py:40-49`；`plugins/deepseek/templates/dashboard.html`
- **现象**：groups 表没有 `group_name`，仪表盘只显示 `group_id`、状态、时间、token。
- **影响**：多群运营时很难分辨“这个号是哪个群”，只能靠记忆或逐个点开。
- **建议**：入站事件里本来就有 `group_name`，落库或缓存显示；增加搜索/排序。

### U-14【高摩擦】保存与长操作缺少真实反馈

- **位置**：`plugins/deepseek/templates/group.html:306-331`、`:334-343`；`plugins/deepseek/templates/mcp.html:76-86`
- **现象**：
  - 群设置页连续发 3 个请求（群设置/风格/工具），完全不看 `response.ok`，最后无条件显示“✅ 已保存”；
  - MCP 保存同样不检查结果；
  - “立即抽取记忆 / 立即学习”用 `fetch(...).then(r=>r.json())`，没有 `try/catch`、不禁用按钮；500 时浏览器拿到 HTML 错误页，提示永久停在“抽取中…”。
- **影响**：用户以为保存/执行成功，实际部分或全部失败；长操作看起来卡死。
- **建议**：逐个检查响应并指出失败项；按钮禁用 + 超时 + `try/catch/finally`；超过 30 秒的操作改成后台任务 + 轮询状态。

### U-15【高摩擦】报表窗口（GUI）拉数据要等满超时

- **位置**：`ui/report_window.py:137-177`
- **现象**：后台线程新建 event loop 调 `bot.get_group_list()`，响应由主循环回填；跨线程 `set_result` 不会唤醒新 loop，实测每次调用要等满 30 秒 `wait_for` 才处理。同时从后台线程直接调 DearPyGui。
- **影响**：打开报表窗口明显卡顿，群/好友列表可能一直不刷新。
- **建议**：用 `asyncio.run_coroutine_threadsafe(..., globals.event_loop)` 回主循环，UI 更新切回 UI 线程。

### U-16【中摩擦】会话过期没有统一处理

- **位置**：`ui/web/templates/index.html:241-263`
- **现象**：只在页面加载时尝试用 localStorage 里的密码自动登录；面板开着超过 24 小时后，后续 fetch 全部 401，页面静默变成空数据/0，不会回到登录页。
- **影响**：用户以为机器人掉线或数据丢了。
- **建议**：封装统一 `api()`，遇到 401 清状态并显示登录页。

### U-17【中摩擦】Socket.IO 从公网 CDN 加载

- **位置**：`ui/web/templates/index.html:233`
- **现象**：`https://cdn.socket.io/...`；内网/受限网络下实时日志失效，只有控制台一句 `console.warn`。
- **影响**：日志页切过去还能靠 `/api/logs` 拉一次，但“实时”体验消失，用户不知道原因。
- **建议**：把客户端放到本地 `static/`，失败时在面板提示“实时日志不可用，刷新查看”。

### U-18【中摩擦】没有模型测试与健康状态

- **位置**：`plugins/deepseek/templates/settings.html`（服务商卡片）；`plugins/deepseek/templates/dashboard.html`
- **现象**：服务商需要手填 base_url 和模型 ID，没有“测试连接/拉取模型”；仪表盘只显示 token 用量，没有最近失败/连续失败。
- **影响**：Key 或模型 ID 错误时，非 @ 轮会静默失败，用户只能翻日志猜。
- **建议**：每个服务商加“测试连接”（发一个极小请求）；仪表盘显示最近 N 次模型失败、连续失败次数和最后一次错误摘要。

### U-19【中摩擦】GUI 与 Web 同时开启时日志分流

- **位置**：`main.py:139`；`core/events.py:46-121`
- **现象**：`enable_web_admin=true` 时 bot logger 指向 Web，桌面日志窗口收不到发送/API 日志；入站消息仍由 `events.py` 直接写 GUI。
- **影响**：GUI 用户会觉得“日志少了一半”，两个界面的信息不一致。
- **建议**：日志总线同时投递到 GUI 和 Web，或明确提示“启用 Web 后桌面日志仅显示入站消息”。

### U-20【优化】没有“重启/重连”操作

- **位置**：`ui/web/server.py`（无对应接口）；`main.py` 重连循环
- **现象**：面板只能改配置，不能触发重连/重启；重连次数耗尽后进程停住，只能去控制台重启。
- **影响**：配合 U-01，面板在故障时几乎帮不上忙。
- **建议**：提供“重连”与“重启进程”按钮（后者需二次确认），或让配置保存后自动重连。

## 3. 群成员体感

### U-21【高摩擦】直接 @ / 回复也可能被 `[nospeak]` 静默

- **位置**：`plugins/deepseek/Core/prompts.py:28-34`；`plugins/deepseek/Core/engine.py:155-167`、`:1527-1549`
- **现象**：`[nospeak]` 规则对所有群轮次生效；`forced`（@/回复）只绕过粗筛和判官，并不强制回复。模型判断“没必要”时，用户直接 @ 也收不到任何回应。
- **影响**：用户会认为机器人没听见或不理人，信任感下降。
- **建议**：forced 轮加硬规则“被 @/回复必须给回应，不能只输出 `[nospeak]`”；或在 `_emit_final` 检测到 forced 且正文为空时补一句极短回应。

### U-22【中摩擦】非 forced 轮失败时完全沉默

- **位置**：`plugins/deepseek/Core/engine.py:203-208`
- **现象**：只有 forced 轮失败会发“（响应失败，请稍后再试）”；判官放行但模型调用失败的普通消息没有任何反馈。
- **影响**：群友不知道是没被选中还是机器人坏了。
- **建议**：失败时给触发者一个短提示（可全局冷却），或在面板健康状态里暴露。

### U-23【中摩擦】回复太长会刷屏，且群级不能调长度/速度

- **位置**：`plugins/deepseek/Core/config.py:166-169`；`plugins/deepseek/Core/reply.py:239-245`；`plugins/deepseek/templates/group.html:44-75`
- **现象**：默认 `split_reply=true`、单条 100 字、条间 600–1800ms；群级覆盖只有“分条发送 开/关”，没有单条字数、延迟、真艾特。
- **影响**：一个 300 字回答会变成 4–5 条气泡；不同群只能共用一套全局节奏。
- **建议**：把 `split_max_len`、延迟、`real_at_on` 放进群级覆盖；或提供“简短/正常”预设。

### U-24【中摩擦】主动唤醒/搭话默认开启

- **位置**：`plugins/deepseek/Core/config.py:108-117`
- **现象**：`wake_on=true`、`speakup_on=true`，每 30 分钟 10% 概率 + 每 20 次必触发。
- **影响**：只想让它被动答疑的群也会突然收到自言自语；新用户可能被吓到。
- **建议**：首次启用群时让用户选“被动回复 / 会主动开口”，或默认关闭 `speakup_on`。

### U-25【优化】引用回复默认关闭

- **位置**：`plugins/deepseek/Core/config.py:161`
- **现象**：`quote_reply_on=false`。
- **影响**：快群里回复晚到一两分钟时，没有引用很难判断在回谁。
- **建议**：至少对 @/回复触发的轮次默认引用，或把开关放到群设置更显眼的位置。

### U-26【中摩擦】没有面向普通群成员的帮助入口

- **位置**：`plugins/deepseek/deepseek.py`（公共指令仅 `#sl`）
- **现象**：`/ai` 帮助是主人专属，`/ai 打断` 全员可用但没人知道；入群问候提过能力，但很快被刷走。
- **影响**：成员不知道可以 @ 它、发图片/文件、让它提醒，也不知道能打断长任务。
- **建议**：加公共 `@机器人 帮助` 或 `#help`，列 3–5 条最常用能力；打断指令写进去。

### U-27【优化】长跑期间普通消息被投成插队，不保证逐条回复

- **位置**：`plugins/deepseek/deepseek.py:_divert_to_loop`；`plugins/deepseek/Core/loop_run.py`
- **现象**：长跑进行中，普通群消息被投进当前任务的插队通道，而不是排队开新轮。
- **影响**：用户发的问题可能被任务模型顺带看到，也可能完全没被回应。
- **建议**：在长跑通知/公开帮助里说明该行为；或对插队消息承诺“任务结束后统一回应”。

### U-28【优化】私聊白名单外用户完全无反馈

- **位置**：`plugins/deepseek/deepseek.py:_handle_private`
- **现象**：非白名单私聊直接忽略，不回复。
- **影响**：陌生人会反复发或认为机器人坏了；对运营者也没有提示。
- **建议**：一次性礼貌拒绝（可全局冷却），或在文档/群公告说明私聊范围。

## 4. 配置与调参

### U-29【高摩擦】`split_max_len` 没有下限（填 0 会卡死）

- **位置**：`plugins/deepseek/templates/settings.html:168`；`plugins/deepseek/Core/config.py:379-385`；`plugins/deepseek/Core/reply.py:110-135`
- **现象**：设置页“单条最大字数”没有 `min`，后端 `_as_int` 也没有下限；填 0/负数后，任意非空回复会在 `_hard_split` 里无限循环。
- **影响**：整个 bot 卡死，不只是体验问题。
- **建议**：输入框加 `min=1`，配置侧强制下限；保存时对明显危险的组合给出确认。

### U-30【中摩擦】设置页 24 个分组一长条，缺导航/搜索

- **位置**：`plugins/deepseek/templates/settings.html`
- **现象**：从账号/模型到多模态共 20+ 个 fieldset，只能一路滚动。
- **影响**：找一个选项（例如“心情每日上限”）需要反复滚动；新用户容易漏看关键配置。
- **建议**：左侧分组导航/锚点，或折叠面板 + 关键字搜索。

### U-31【中摩擦】服务商配置需要手填模型 ID

- **位置**：`plugins/deepseek/templates/settings.html:250-400`
- **现象**：没有“拉取模型列表”，模型 ID 全靠手输；拼错后保存能过，调用才失败。
- **影响**：非开发用户很难配对；错误反馈滞后。
- **建议**：加“测试连接/拉取模型”按钮；至少对 ID 做一次探测或给出常见示例。

### U-32【优化】仪表盘 token 列是三个裸数字

- **位置**：`plugins/deepseek/templates/dashboard.html`
- **现象**：显示“命中 / 未命中 / 输出”，没有百分比、成本或趋势。
- **影响**：运营者难以判断“这个群是不是太贵了”。
- **建议**：加命中率、按模型/服务商估算成本、异常高消耗提示。

### U-33【优化】记忆页没有分页

- **位置**：`plugins/deepseek/Core/storage.py:1204-1214`；`plugins/deepseek/templates/memory.html`
- **现象**：`list_memories` 返回该用户全部记忆，页面一次渲染。
- **影响**：长期使用的用户记忆很多时，页面会变慢、难浏览。
- **建议**：分页或“加载更多”，加关键字过滤。

### U-34【优化】MCP 配置需要手写 JSON

- **位置**：`plugins/deepseek/templates/mcp.html`
- **现象**：stdio/http 配置都填在 textarea 里，只有一行提示。
- **影响**：对不熟悉 MCP 的运营者门槛高，容易写错。
- **建议**：按类型给表单字段（command/args/env 或 url/headers），保留“高级 JSON”折叠区。

## 5. 文档与默认值一致性

### U-35【高摩擦】README、默认配置、代码兜底三套地址

- **位置**：`README.md:240`、`configs.py:19`、`config_defult.json`、`main.py:61`
- **现象**：`8080` / `3001` / 公网 IP 三种值并存；`config_defult.json` 文件名拼写错误且内容过期。
- **影响**：首次配置按文档填却连不上；用户不知道哪个才是“官方默认”。
- **建议**：统一默认值，删除/重命名过期文件，README 与代码默认值保持单一来源。

### U-36【中摩擦】README 未说明面板依赖连接成功

- **位置**：`README.md:254-267`；`docs/web-admin.md`
- **现象**：文档写“启用后启动程序，访问 8081”，但实际要等 WS 连接成功。
- **影响**：NapCat 未就绪时用户以为面板坏了。
- **建议**：文档明确说明；或按 U-01 改进行为。

### U-37【中摩擦】文档与默认监听地址不一致

- **位置**：`README.md:261` vs `configs.py:23`
- **现象**：README 推荐 `127.0.0.1`，生成的默认是 `0.0.0.0`。
- **影响**：用户以为按文档配置了，实际行为不同。
- **建议**：默认改为 `127.0.0.1`，需要局域网访问时由用户显式修改并提示。

### U-38【优化】品牌与场景不一致

- **位置**：`ui/web/templates/index.html` 登录页/标题
- **现象**：面板叫 “NapCatBot”，但项目叫“大肥鱼”，且支持 official 通道。
- **影响**：用官方机器人时看到 NapCat 会困惑。
- **建议**：改为项目名或中性的“QQ Bot 管理台”。

- **提示词体系成熟**：人设、`[nospeak]`、CQ 码禁令、时间戳规则、群聊/私聊场景区分，都是围绕“像群友”设计的。

- **文档体量大**：README 有目录和快速开始，插件/DSL/API 文档齐全。
