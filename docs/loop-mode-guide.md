# 长跑模式（loop）指南

普通对话一轮最多走 50 个工具轮（后台苏醒轮只有 8 轮），长任务（爬帖、批量整理、
多步操作）会被中途截断，需要主人反复说「继续」。**长跑模式**经主人授权后，AI 在
指定群围绕**一个任务**连续自主工作、无工具轮上限，直到自己调用收尾工具或主人叫停。

## 它解决什么

1. **连续工作**：一轮接一轮地跑，每轮之间自动注入「续跑通知」，不用人催「继续」。
2. **定期露脸**：每 `loop_every_rounds`（默认 5）个工具轮必须在群里发一句进展，
   防止长时间闷头干活群里死寂；到点没说会被摘掉工具强制汇报一次。
3. **自动压缩上下文**：每个工具轮的模型响应都回传真实 prompt_tokens，引擎据此
   外推当前水位；达到「输入预算（模型上下文总 token 减去输出 max_tokens）的
   `loop_compact_percent`%（默认 80%）」时，在请求模型之前主动把前面的工具过程
   压成滚动进展纪要，保留开头的系统块和最近 `loop_keep_rounds`（默认 4）个完整
   工具轮。模型总上限取 `loop_context_limit_tokens` 配置；留空（`0`，默认）时
   先按 `loop_compact_threshold_chars`（默认 4 万字）的字符阈值兜底，一旦请求
   撞上上下文超长报错，会从报错文案里自动学习该模型的实际上限（随后按真实 token
   水位提前压缩），并强制压缩后自动重试（每次请求最多 3 回）。纪要只存在内存的
   `loop_ctx` 里、跨续跑轮注入重建出的上下文，但不写消息表。
4. **双授权入口**：主人手动开启，或 AI 用 `loop_request` 工具申请、主人私聊批准。
5. **多重收尾**：AI 调 `loop_finish` 结束；主人 `/ai 循环 关` 叫停；连续
   `loop_idle_turn_limit`（默认 3）轮没做任何工具操作判定空转自动结束；异常/重启
   不会无限挂着。

```
主人 /ai 循环 <任务>                AI 调 loop_request 工具
        │                                    │
        ▼                                    ▼
 loop_sessions 落 running            loop_requests 落 pending + 私聊主人卡片
        │                                    │
        └──────────────┬─────────────────────┘
                       ▼
        LoopManager.start() → asyncio 任务 _worker
                       │ 整个长跑期间持有 group_lock
                       ▼
   注入「长跑任务通知」→ engine._run_turn(loop_ctx=...)
        │  无轮数上限 / 每 N 轮强制汇报 / 自动压缩
        ▼
   注入「长跑续跑通知」→ 再跑一轮 …… 直到：
   loop_finish（done，结果私聊主人）/ 主人叫停（stopped）
   / 空转保护（done）/ 异常（error，私聊主人）
```

## 主人怎么用

指令前缀默认 `/ai`，`循环`、`长跑`、`loop` 三个动词等价（只认主人 QQ）：

| 指令 | 作用 |
|---|---|
| `/ai 循环 <任务内容>` | 在**当前群/私聊**开启长跑，任务文本原样作为目标 |
| `/ai 循环` 或 `/ai 循环 状态` | 查看本群长跑状态（任务、已跑工具轮数、压缩次数） |
| `/ai 循环 关` | 请求停止：她做完当前这一轮后干净退出（不硬杀协程） |
| `/ai 循环 同意 <编号>` | 批准 AI 的长跑申请（群里或私聊发都行） |
| `/ai 循环 拒绝 <编号> [理由]` | 拒绝申请；拒绝通知会落进申请所在群的上下文 |

开启后群里先发一条 `🚀 长跑已启动（任务#N）：…`。长跑进行中：

- **普通群友消息不排队**：worker 整段持有群锁，普通消息走「插队通道」，在她两次
  请求模型之间的安全点注入上下文（和 `/ai 打断` 同一条通道，全员可用）；恰好赶在
  两个长跑轮之间的极窄窗口则直接落库，下一轮重建窗口时看得到。
- 主人 `/ai ...` 指令与 `/ai 打断` 维持原路径，不需要等锁。
- 结束时群里发 `✅ 长跑任务#N已完成`，**结果摘要私聊发给主人**；异常中止同样私聊
  报错。

## AI 怎么用

两个内置工具（不计入风险工具；`loop_finish` 仅长跑中可用）：

- `loop_request(task, reason?)`：当预估任务需要连续很多步、可能超过普通工具轮上限
  时调用。只落申请 + 私聊主人，**不会本轮启动**；返回文案会明确告诉她这一点。
- `loop_finish(summary)`：宣告任务完成，`summary` 作为结果私聊汇报主人。长跑通知
  里反复强调「做完必须调 loop_finish，不要自顾自停下」。

## 行为约定

- **任务型，不是常驻空转**：一个长跑绑定一个任务，跑完就结束；不是开了以后永远
  在群里自主活动。
- **每 N 轮强制汇报**：中间任意一轮模型自己发了插话正文就重新计数；连续 N 个只有
  工具调用的静默轮后，下一轮模型请求被摘掉工具，要求先用一两句群聊口语汇报，汇报
  走与普通插话完全相同的发送/落库路径，然后恢复工具继续干。
- **压缩只动内存**：自动压缩只改内存里的 messages，DB 全量历史不受影响；滚动纪要
  存在 `loop_ctx` 中，每个续跑轮重建窗口时作为系统块注入对话窗正前方（重启即失），
  下次压缩时旧纪要会并入新纪要，不会堆积。旧图片直接丢弃，工具内容截断后进便宜
  模型做滚动纪要（复用 summary 模型路由）。压缩次数写回 `loop_sessions.compacts`，
  状态指令里可查。
- **重启/热重载即中断**：worker 是内存协程，重连会重建插件实例。`on_start` 对账把
  残留的 `running` 会话统一置为 `interrupted`（错误原因「插件重启，长跑中断」），
  **不自动复活**；需要继续请主人再开一次。
- **会话串行**：同群同时只能有一个长跑，重复开启会被拒绝；申请在已有长跑时调用会
  直接提示「已经在进行中，继续干活即可」，不落申请。
- 群设置可单独关 `loop_on`：关闭后主人指令与 `loop_request` 都会被拒绝，进行中的
  长跑在下一轮边界自动停止。

## 配置

Web 全局设置页「长跑模式」分组，或 `plugins/deepseek/config.json`：

| 键 | 默认 | 说明 |
|---|---|---|
| `loop_on` | `true` | 总开关；在每群「群设置」可单独覆盖 |
| `loop_every_rounds` | `5` | 连续多少个静默工具轮后强制汇报一次 |
| `loop_context_limit_tokens` | `0` | 模型上下文总 token 数；`0`=自动（从超长报错学习，学到前按字符阈值兜底） |
| `loop_compact_percent` | `80` | 真实 prompt token 用到输入预算的百分之多少就提前压缩（20~95） |
| `loop_compact_threshold_chars` | `40000` | 兜底字符阈值：未知模型 token 上限时按此触发压缩 |
| `loop_keep_rounds` | `4` | 压缩时尾部原样保留的完整工具轮数 |
| `loop_idle_turn_limit` | `3` | 连续多少个续跑轮无工具操作则空转自动结束 |

只有 `loop_on` / `loop_every_rounds` 允许按群覆盖；压缩相关参数均为全局参数。

## 数据留痕

DB v16 起新增（见 `Core/storage.py` 迁移）：

- `loop_sessions`：每次长跑一行（任务、状态 `running/done/stopped/error/
  interrupted`、发起人 `owner/ai`、关联申请号、累计工具轮数、压缩次数、结果、
  错误、起止时间）。
- `loop_requests`：申请审批状态机（`pending/approved/rejected` + 决定人/时间），
  pending 只能决策一次。
- 每个续跑轮在既有 `bg_runs` 表里留一条 `kind='loop'` 的运行记录（trace 含
  interim/tool/loop_speech/compact 步骤），后台运行页可查。
