# EPK《变量说明》与当前 Slang 实现对照表

- **对照来源**：`docs/slang/variable.html`（Wayback Machine 存档，原站 `http://myepk.club/variable.html`，页面更新日期 **2020-04-04**，酷Q时代的 EPK/铃心自定义变量规范）
- **对照基准（当前实现）**：
  - `plugins/slang/slang.py`（插件层：消息匹配、上下文变量、回复队列、规则管理 API）
  - `plugins/slang/Core/functions.py`（内置函数，32 个）
  - `plugins/slang/api/classes.py`（置数组 / 置字典）
  - `plugins/slang/Core/init.py`（控制流：判断 / 比较- / 循环-）
  - `plugins/slang/Core/main.py`、`ast.py`（AST 解释器）
- **生成日期**：2026-09-27

## 图例

| 标记 | 含义 |
|---|---|
| ✅ | 已实现，语义基本一致 |
| 🟡 | 部分实现 / 存在等价物（名称、参数或语义有差别，表中说明） |
| ❌ | 未实现 |
| ➕ | 当前实现独有、原文档没有的功能 |

> 总体结论：原文档约 130 项功能/变量中，**完全对得上的约 12 项，有等价物或部分实现的约 25 项，其余约 90 项未实现**。当前实现走的是"真解释器 + Python 注册函数"路线，而 EPK 是"回复文本变量替换"路线，二者架构不同；未实现项大量集中在群管操作、事件订阅、词库、回复限制、IO 流、文件/磁盘操作等模块。

## 2. 匹配规则

| 文档功能 | 状态 | 当前实现 / 差别 |
|---|---|---|
| 完全匹配（区分大小写，无子关键词） | ✅ | `exact`：`raw_message == match_content`（`slang.py:208`），语义一致 |
| 模糊匹配（**不区分**大小写） | 🟡 | `fuzzy`：`match_content in raw_message`（`slang.py:210`）。**差别：当前区分大小写**；且不提供子关键词 |
| 前缀匹配（区分大小写） | ❌ | 匹配类型只有 `exact/fuzzy/regex`，无前缀类型（DB CHECK 约束，`slang.py:120`） |
| 正则匹配（默认为**完全匹配**，子关键词=第 1 个捕获组） | 🟡 | `regex` 用的是 `re.search()`（`slang.py:213`）。**差别：①永远是查找匹配，相当于文档默认就带 `[查找]`，无法表达 fullmatch；②捕获组不会提取为子关键词/变量** |
| 【内容x】取第 x 个子表达式 | ❌ | 正则捕获组结果未注入任何变量 |

## 44. 从 EPK 迁移到当前 Slang 的注意事项

1. **算式必须改写**：`× → *`、`÷ → /`、`^ → **`、`\（求整）→ //`；位运算、`@` 四舍五入、逗号分步无对应实现；算式中不能出现变量名，需先取出数值再拼算式（或由调用方保证替换后是纯数字）。
2. **正则规则默认行为相反**：EPK 正则默认 fullmatch、加 `[查找]` 才 search；当前一律 search。从 EPK 搬来的正则若要保持全匹配，需自行加 `^...$`。
3. **模糊匹配**：EPK 忽略大小写，当前区分大小写，必要时在规则层改写文本或用正则 `(?i)`。
4. **行号基数不统一**：`取出一行` 为 0 基，`删除一行` 为 1 基，迁移时注意。
5. **子关键词/捕获组缺失**：正则捕获组、模糊/前缀的剩余文本都不会自动注入，需在 Slang 代码内自行解析 `消息内容`。
6. **权限、频控、事件、群管动作**全部需要在 Python 插件层另行实现，规则层无对应变量。
7. **同名不同义**：EPK 的 `回复[关键词]` 是调用另一条规则；当前 `回复` 是发送消息。EPK 的 `判断` 是文本相等比较（4 参）；当前 `判断` 是条件分支（3 参）。
