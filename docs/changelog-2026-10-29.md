# 2026-10-29 更新汇总（v2026.10.29.1）

## 长跑模式：按真实 token 水位自动压缩上下文

之前长跑只靠**字符数估算**（`loop_compact_threshold_chars`，默认 4 万字）判断
要不要压缩，工具 schema、系统提示词都没算进去，和模型真实上下文窗口对不上：
不同模型窗口有大有小，既可能提前丢信息，也可能顶到报错才自救。本次更新：

| # | 更新 | 入口 | 默认 |
|---|---|---|---|
| 1 | 每次模型请求回传的真实 `prompt_tokens` 记为水位采样，下一轮按体量增长外推，到点**请求前主动压缩**（不再等报错） | 无 | 自动 |
| 2 | 新增模型上下文总 token 配置；留空为自动——先按字符阈值兜底，撞上超长报错后从报错文案自动学习该模型实际上限，之后按真实 token 水位压缩 | Web 设置页「长跑模式」 | `loop_context_limit_tokens=0`（自动） |
| 3 | 新增提前压缩水位百分比（输入预算 = 模型总上限 − 输出 `max_tokens`，给回复留余量） | 同上 | `loop_compact_percent=80` |
| 4 | 滚动进展纪要跨续跑轮保留：纪要存 `loop_ctx`，每个续跑轮重建窗口时注入对话窗正前方；旧纪要在下一次压缩时并入新纪要，不堆积、不丢任务进展 | 无 | 自动 |

压缩切点、尾部完整工具轮保留、撞上限强制压缩后重试（每请求最多 3 回）等原有
行为不变；`loop_compact_threshold_chars` 保留为「未知模型 token 上限」时的兜底
阈值。详见 [loop-mode-guide.md](loop-mode-guide.md)。
